Regla de oro: Front = lo que ves · Back = lo que piensa · BD = lo que recuerda.

2 · Cómo se hablan (API + JSON)

  • API = puente que permite que 2 sistemas se comuniquen aunque no hablen el mismo idioma.
  • API REST = el tipo de API más usado en la web.
  • JSON = el idioma de los datos: objetos { } y arreglos [ ].
  • Request = lo que el front manda (petición).
  • Response = lo que el back responde.
Front → manda JSON (request) → Back → consulta BD → Back → responde JSON (response) → Front pinta
Desacople: el backend no sabe si le habla una web, un celular u otro sistema. Solo recibe y responde JSON.

3 · CRUD — las 4 operaciones básicas

LetraOperaciónEn tu app

Todo modelo de datos en una app se maneja con CRUD. Es la base universal.

5 · El modelo "Tarea" (los datos)

Los 4 campos

  • nombre — qué hay que hacer
  • responsable — quién la toma
  • estatus — en qué estado está
  • descripcion — detalle / notas

(+ id = número único que da la base de datos sola)

Estatus = valores cerrados

  • 🟠 pendiente — todavía no
  • 🔵 en_progreso — se está haciendo
  • 🟢 hecha — terminada
El estatus NO es texto libre: solo estos 3 valores. Eso es normalización.

8 · Reglas de oro del código

const vs let

  • const = no cambia (arreglos, objetos)
  • let = cambia (contadores, acumuladores)
  • Pista de Leo: "¿va a cambiar? → let"

Selector de elementos

  • # = id · . = clase
  • getElementById("id") sin #

Arreglo vs objeto

  • Arreglo [ ] = lista, se agarra por posición [0]
  • Objeto { } = ficha con nombre: valor, se agarra con punto .campo

Otras

  • === compara valor Y tipo (no ==)
  • Punto y coma ; al final
  • camelCase: cargarTareas (sin espacios, sin acentos)
  • IDs con guion: input-nombre
